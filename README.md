# Лабораторийн ажил №5 — REST API системийн тест

**Оюутны нэр:** Б. Баяргүн  
**Оюутны код:** B222270085

## 1. Зорилго

Энэхүү лабораторийн ажлын зорилго нь REST API-ийн бүртгэлийн үйл ажиллагаанд системийн тест хийх, тестийн оролтын өгөгдлийг эквивалент ангилал болон хязгаарын нөхцөлөөр сонгох, хүлээгдэх үр дүнг тодорхойлох, Postman ашиглан тест хэрэгжүүлэх, Newman-аар автоматжуулан PASS, FAIL, DOWN туршилтын үр дүнг баталгаажуулахад оршино.

## 3. Тестийн дизайны таван алхам

**Алхам 1. Оролтын нөхцөлүүдийг тодорхойлох**

Оюутны бүртгэл байгаа эсэх, оюутны төлөв, хичээлийн бүртгэл байгаа эсэх, урьдач нөхцөлүүд хангагдсан эсэх, хүсэлтийн заавал байх талбарууд болон JSON формат зөв эсэхийг тодорхойлсон.

**Алхам 2. Эквивалент ангилалд хуваах**

Оролтын нөхцөл бүрийг хүчинтэй болон хүчингүй утгуудын ангилалд хуваасан.

**Алхам 3. Төлөөлөх утгууд сонгох**

Ангилал бүрээс `active`, `inactive`, `UNKNOWN_TC02`, `CS201`, `CS202`, хоосон массив зэрэг төлөөлөх утгуудыг сонгосон.

**Алхам 4. Тестийн спецификаци боловсруулах**

Нийт 10 тестийн тохиолдол боловсруулж, хүсэлтийн оролт, HTTP статус болон хүлээгдэх `result` утгыг тодорхойлсон.

**Алхам 5. Тест хэрэгжүүлж, автоматжуулах**

Postman ашиглан PUT болон POST хүсэлтүүд, Post-response assertion-уудыг хэрэгжүүлсэн. Newman ашиглан PASS, зориуд буруу oracle бүхий FAIL, сервер унтарсан үеийн DOWN туршилтуудыг ажиллуулсан.

## 5. Тестийн спецификаци

| ID   | Тестийн нэр                       | Тестийн нөхцөл                        | HTTP статус | Хүлээгдэх result                           |
| ---- | --------------------------------- | ------------------------------------- | ----------- | ------------------------------------------ |
| TC01 | Амжилттай бүртгэл                 | Идэвхтэй оюутан, шаардлага хангагдсан | 201         | `OK`                                       |
| TC02 | Оюутан олдохгүй                   | Бүртгэлгүй оюутны ID                  | 200         | `ERROR_NO_STUDENT`                         |
| TC03 | Идэвхгүй оюутан                   | `status=inactive`                     | 200         | `ERROR_INACTIVE_STUDENT`                   |
| TC04 | Хичээл олдохгүй                   | Бүртгэлгүй хичээлийн ID               | 200         | `ERROR_NO_COURSE`                          |
| TC05 | Урьдач нөхцөл хангаагүй           | `coursesTaken=[]`, шаардлага `CS201`  | 200         | `ERROR_PREREQUISITES`, `missing=["CS201"]` |
| TC06 | Урьдач нөхцөлгүй                  | `prerequisites=[]`                    | 201         | `OK`                                       |
| TC07 | Урьдач нөхцөлийн заримыг хангасан | `CS201` судалсан, `CS202` дутуу       | 200         | `ERROR_PREREQUISITES`, `missing=["CS202"]` |
| TC08 | Заавал байх талбар дутуу          | `studentID` байхгүй                   | 400         | `ERROR_BAD_REQUEST`                        |
| TC09 | Буруу JSON                        | JSON синтакс алдаатай                 | 400         | `ERROR_BAD_JSON`                           |
| TC10 | Давхар алдаа                      | Идэвхгүй оюутан, байхгүй хичээл       | 200         | `ERROR_INACTIVE_STUDENT`                   |

## 6. Newman автоматжуулалтын үр дүн

### 6.1 PASS тест

**Файл:** `results/newman-pass.txt`

Ажиллуулсан команд:

```bash
newman run lab-05-API.postman_collection.json 2>&1 | tee results/newman-pass.txt
echo "exit=${PIPESTATUS[0]}"
```

| Үзүүлэлт   | Executed | Failed |
| ---------- | -------: | -----: |
| Iterations |        1 |      0 |
| Requests   |       23 |      0 |
| Assertions |       23 |      0 |

**Exit code:** 0

_Энэ хүснэгтийг эцсийн `newman-pass.txt` гаралттай тулгаж баталгаажуулна._

### 6.2 FAIL тест

**Файл:** `results/newman-fail.txt`

Ажиллуулсан команд:

```bash
newman run lab05-collection-fail.json 2>&1 | tee results/newman-fail.txt
echo "exit=${PIPESTATUS[0]}"
```

| Үзүүлэлт   | Executed | Failed |
| ---------- | -------: | -----: |
| Iterations |        1 |      0 |
| Requests   |       23 |      0 |
| Assertions |       23 |      1 |

**Exit code:** 1

Амжилттай бүртгэлийн HTTP статусыг зориуд `200` гэж хүлээсэн боловч сервер `201 Created` буцаасан. Newman энэ зөрүүг илрүүлж нэг assertion FAIL болгосон. Бусад assertion амжилттай ажилласан.

### 6.3 DOWN тест

**Файл:** `results/newman-down.txt`

Ажиллуулсан команд:

```bash
newman run lab-05-API.postman_collection.json 2>&1 | tee results/newman-down.txt
echo "exit=${PIPESTATUS[0]}"
```

Серверийг унтраасны дараа Newman хүсэлтүүдийг илгээхэд `ECONNREFUSED` алдаа үүсэх ёстой.

| Үзүүлэлт   |   Executed |     Failed |
| ---------- | ---------: | ---------: |
| Iterations | Бодит утга | Бодит утга |
| Requests   | Бодит утга | Бодит утга |
| Assertions | Бодит утга | Бодит утга |

**Exit code:** DOWN туршилтын бодит утгыг оруулна.

DOWN нь сервертэй холболт үүсгэж чадаагүй интерфейсийн түвшний алдаа юм. Харин FAIL туршилт нь сервер зөв хариу буцаасан боловч тестийн oracle буруу байснаас үүссэн assertion алдаа юм.

## 7. Дүгнэлт

1. Энэхүү лабораторийн ажлаар REST API-ийн бүртгэлийн үйл ажиллагаанд системийн тест боловсруулж, автоматжуулсан.
2. Тестийн дизайны таван алхмаас оролтын нөхцөлүүдийг эквивалент ангилалд хувааж, тохирох төлөөлөх утгууд сонгох нь хамгийн их бодол шаардсан.
3. Учир нь оюутны төлөв, хичээлийн бүртгэл болон урьдач нөхцөлүүд хоорондоо хамааралтай байсан.
4. Урьдач нөхцөлгүй хичээлд урьдач нөхцөл дутсан алдаа хүлээх нь логикийн хувьд боломжгүй хослол болохыг тодорхойлсон.
5. Давхар алдааны тестээр идэвхгүй оюутан болон байхгүй хичээл зэрэг тохиолдоход `ERROR_INACTIVE_STUDENT` түрүүлж буцаж байгааг шалгасан.
6. TC07 тестийн эхний Newman ажиллуулалтад `missing` массив хүлээгдсэн үр дүнтэй зөрсөн боловч тестийн өгөгдлийг зассанаар асуудлыг шийдвэрлэсэн.
7. Иймээс баталгаажсан бүтээгдэхүүний согог илрүүлсэн гэж дүгнээгүй бөгөөд эхний зөрүү нь тестийн тохиргоотой холбоотой байсан.
8. FAIL туршилтаар зориуд буруу oracle ашиглахад Newman алдааг илрүүлж `exit code 1` буцаадгийг баталгаажуулсан.
9. DOWN туршилт нь сервертэй холбогдох боломжгүй үеийн алдааг assertion-ийн алдаанаас ялгаж ойлгох боломж олгосон.
10. Postman болон Newman ашигласнаар тестүүдийг дахин ажиллуулах, үр дүнг текст файлаар хадгалах, CI quality gate-д ашиглах үндсэн ойлголтыг эзэмшсэн.
